## Singleton-Class Amendment

**Accepted; no statistical reason to exclude a dataset or restart completed normal-class tasks.** The amended N:122-152 uses shuffled three-fold KFold only when outer-training class counts cannot support stratification; otherwise the existing stratified folds and selection grids are unchanged. Both CART and RF use the same training-only folds and scoring rule. The outer test remains outside selection. This does not create test leakage or by itself make the held-out comparison unacceptable.

The limitation is intrinsic: the singleton is held out in one inner fold, so that fold's learner has never seen its class and cannot predict it. Inner accuracy is therefore pessimistic for that example and cannot reliably assess rare-class generalization; hyperparameter selection may be noisy or favor majority-class performance. Overall-accuracy selection remains the declared target. Do not interpret this fallback, or a volatile class-specific balanced-accuracy component, as reliable estimation of the singleton class's performance. No choice of cross-validation can fix that lack of training observations.

Do not fabricate confidence intervals or recover individual scores from means and win counts.

2. **[P1] The paper presents estimated mixed cost as fitting time and overstates the budget interpretation.** B:251-255 and G:318-322 scale entire-bank times, including overhead, by selected tree counts. They do not measure the selected trees' costs or a standalone mixture fit. Linear overhead scaling is generally unsuitable for small ensembles; tree costs vary, and parallel wall time need not be additive. The two scripts default to `n_jobs=1`, but historical thread/load settings are not recorded. M:129-140 and its abstract should explicitly say estimated allocated cost for legacy mixtures. A:526-535 fixes both the 0.7 s line and highlighted configurations; there is no train-only selection procedure. This supports an exploratory illustration, not prospective budget performance. **Action:** Time actual mixed fits and training-only selection; report budget violations. Treat `estimated_cost_s` in S57 as shard-planning estimates, not additional measured result times.

3. **[P1] Prefix mixtures reuse bootstrap slots within an ensemble.** F:99-105 generates seeds and samples from the same forest seed independently of k. Equal-capacity k banks therefore have identical bootstrap samples by slot. B:217-224 and G:300-307 take each component from index zero. Thus the grid's 15 k=1 + five k=2 trees reuse the first five bootstrap samples across sight depths: 20 estimators, but only 15 slot draws, rather than 20 distinct slot draws. Pure-bank pairing is useful common-random-number control; reusing bags inside a mixture is a different design. It is not test leakage or automatically invalid accuracy, but confounds a claimed diversity/replacement mechanism. **Action:** Use one schedule of distinct slots per ensemble and assign sight levels to disjoint slots independent of labels. Preserve pairing across compared methods, not duplicate slots within the tested mixture. Retain paired-bag mixtures only as an explicitly named ablation; do not infer lower prediction-error correlation without measuring it on training validation data.

4. **[P1] Same seed does not imply size-stable bootstrap prefixes.** F:101 draws all `n_estimators` seeds before any samples. A 100-tree standalone fit and the first 100 trees of a 200-tree fit start sampling at different RNG states. B's five-tree k=3 bank is likewise not bootstrap-paired to its 100-tree k=1,2 banks. Within G, all banks have 200 trees, so cross-k same-slot pairing and within-bank prefix nesting are valid. This distinction explains a source of the old/grid discrepancy; it does not establish that all timing changes have the same cause. **Action:** Generate each tree's bootstrap and split seeds from stable dataset/repeat/slot identifiers, independent of eventual forest size and sight. Test identical prefixes across capacities before any new run, and retain sample hashes. Do not combine the two legacy runs as replications of a fixed seeded estimator.

5. **[P1] Custom k=1 is not established CART equivalence; it has a materially different stopping rule.** T:208-225 and C:119-125,249-255 require a score reduction strictly greater than an absolute `1e-12`; a feasible zero-gain split is rejected. X:16-28 expressly expects the balanced-XOR greedy tree to remain a stump. In contrast, scikit-learn's depth-first CART builder permits a valid zero-improvement split when `min_impurity_decrease=0`, subject to its numerical tolerance ([versioned source, lines 227-229](https://github.com/scikit-learn/scikit-learn/blob/1.7.2/sklearn/tree/_tree.pyx#L227)). Consequently the XOR test demonstrates this implementation's stopping behavior, not an impossibility for CART. **Action:** Call this baseline custom greedy induction; add real CART at identical and deeper capacities. Either harmonize and validate stopping semantics before rerunning, or disclose the difference and retain both baselines. The aggregate impact is unknown without new fits.

6. **[P1] Depth-three all-feature bagging is not a competitive conventional random-forest comparison.** M:84 honestly states the all-feature choice, but keywords, aggregate CSV labels, and broader conclusions risk conflating it with the usual feature-subsampled RF. B:200-208 and G:273-281 set `max_features=None`, `max_depth=3`. This isolates sight inside one constrained custom learner, not practical ensemble quality. Conventional scikit-learn RF exposes feature subsampling with default `sqrt` ([official parameters](https://scikit-learn.org/stable/modules/generated/sklearn.ensemble.RandomForestClassifier.html)); an all-feature RF configuration is a bagging-style comparator, not the missing feature-subsampled baseline. **Action:** Include optimized-library CART, all-feature bagging, and feature-subsampled RF, each allowed deeper trees and training-only tuning. Report controlled matched-capacity and practical tuned comparisons separately. Giving greedy methods more trees while permanently limiting them to depth three does not address R1.

7. **[P1] Resampling uncertainty and sample-selection effects are unresolved.** M:84-90 uses one split; no tuning or uncertainty exists. L:63-70 records exclusions based on slow k=3 fits, so complete-case accuracy is conditional on computational feasibility. The 57 manifest is not demonstrated to be a subset of the unidentified 67. D57 spans 32-12,958 rows and 2-43 features; seven datasets exceed B's default `n*p <= 25,000` filter (five GAMETES datasets, led24, nursery), implying additional selection/overrides that need provenance. K57 has 83 historical events for 82 unique datasets, including 51 timeout events and 32 other/fetch events at varying limits (120 or 300 s), not B's current default 1,800 s. Freeze an outcome-independent revision manifest and retain failures per method rather than discard a dataset because one method times out. T:181-185 applies `min_impurity_decrease` to lookahead terminal gain, while descendant search does not enforce that threshold; tuning it would not have CART's immediate-gain semantics.
